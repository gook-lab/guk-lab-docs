# 부채 위에 게이트 세우기

린터를 한 번도 안 돌린 레포에 `eslint .`를 CI 게이트로 붙이면 아무것도
통과하지 못합니다. 그렇다고 미루면 새 위반이 계속 섞이고요. 그래서 **기존 부채를
베이스라인으로 고정하고, 늘어난 것만 실패시킵니다.**

## 왜 필요했는지

`pig`에서 실측한 부채 (2026-08-19):

| 검사 | 처음 | 원인 |
|---|---|---|
| `tsc --noEmit` | **523건** | 한 번도 안 돌림 |
| `eslint .` | **264건** (그중 `rules-of-hooks` 145건) | 한 번도 안 돌림 |

둘 다 "게이트가 없어서" 쌓인 것입니다. 코드 품질 문제가 아니라 **파이프라인
구멍**이었습니다.

## 두 부채는 다르게 다뤘습니다 — 판별 기준

| | tsc 523건 | eslint 264건 |
|---|---|---|
| 성격 | 대부분 `noUncheckedIndexedAccess` 타입 내로잉 | 잡다 — 실제 버그부터 스타일까지 |
| 수정 위험 | 낮음 (가드·non-null·동일 의미 폴백만, 로직 무변경) | **케이스별 판단 필요** |
| 처리 | **전량 청산** → 0건, 이후 회귀 차단 | 베이스라인 고정 + 점진 청산 |

기계적으로 안전하게 고칠 수 있으면 **한 번에 청산하는 게 좋습니다.** 판단이
필요하면 게이트만 세우고 나중에 갚습니다. 이걸 안 가르면 "언젠가 다 고치면
게이트 세우자"에 갇혔습니다.

린트 안에서도 다시 갈랐습니다. `react-hooks/rules-of-hooks` 145건은 전부 **"훅
호출 전에 early return"**이라는 동일 패턴 — 실제 버그 클래스입니다. 이건 전량
청산했습니다(현재 레포 전체 0건). 남은 106건은 `set-state-in-effect`(26) /
`exhaustive-deps`(23) / `react-refresh`(18) 계열로, 일괄 수정하면 동작이 바뀔
수 있어서 남겨뒀습니다.

## 게이트 구현

`scripts/lint-gate.js` — 100줄 남짓입니다.

1. `npx eslint . --format json`을 돌려 **파일별 위반 수**를 세고
2. `scripts/lint-baseline.json`과 비교합니다
3. **늘어난 파일이 있으면** 그 파일과 증가분을 찍고 exit 1
4. **줄었으면** 통과시키되 `--update` 하라고 안내합니다
5. `--update`는 현재 수치를 베이스라인으로 다시 씁니다

핵심은 4번입니다. 베이스라인은 **한 방향(내려가는 쪽)으로만** 조여집니다.
올라가는 경로가 없으니 부채가 되돌아올 수 없습니다.

전체 합계가 아니라 **파일별**로 세는 것도 의도적입니다. 합계로 세면 A 파일을
3건 고치고 B 파일에 3건 넣어도 통과하기 때문입니다.

## 게이트는 꼭 깨뜨려 보고 커밋합니다

세운 게이트가 실제로 잡는지 **양방향으로** 확인했어요:

```
# 잡는가 — 미사용 변수를 일부러 주입
src/utils/uuid.ts: 0 → 1 (+1)     exit 1  ✓
# 되돌리면 통과하는가
                                   exit 0  ✓
# 줄었을 때 개선 경로로 빠지는가 — 베이스라인을 부풀려서 확인
"3건 줄었습니다 … --update 하세요"  exit 0  ✓
```

통과만 확인하고 커밋하면 **아무것도 안 잡는 게이트**를 세워놓고 안심하게 됩니다.

## 점진 청산 방침

별도의 대규모 청산 작업은 잡지 않습니다. **도메인 작업으로 파일을 건드릴 때
그 파일의 기존 위반도 같이 정리하고 `--update`로 베이스라인을 낮춥니다.**

한 번 돌려보고 방침을 확정했습니다 — 파일 2개(`ConnectorLabelOptionsBar`,
`ColorPickerPopup`)를 정리해서 107 → 106. 워크플로가 실제로 돈다는 걸 확인한
다음에 문서에 적었습니다.

## 함정: 파이프가 종료코드를 삼킵니다

```bash
npm run lint:gate | tail    # $? 는 tail 의 코드 — 실패가 0으로 보인다
```

`npm run lint:gate | tail`로 돌리면 `$?`는 tail의 종료코드라서 **실패가 0으로
보입니다.** 게이트가 조용히 무력화되는 전형적인 경로입니다. CI·훅에는 파이프
없이 직접 붙이거나 `set -o pipefail`을 켭니다. **모든 검증 커맨드에 해당합니다.**

## 설정 파일을 약화시켜 통과시키지 않습니다

`pig`에는 `eslint.config.js` 수정을 막는 훅이 걸려 있습니다:

> BLOCKED: Modifying eslint.config.js is not allowed. Fix the source code to
> satisfy linter/formatter rules instead of weakening the config.

게이트를 세우는 것과 게이트를 낮추는 것은 반대 방향의 일입니다. 규칙을 끄고
싶어진다면, 그건 보통 규칙이 옳다는 신호입니다.

## 옮겨 붙일 때

이 게이트는 ESLint 전용이 아닙니다. **파일별로 수를 셀 수 있는 검사면 뭐든**
같은 틀이 먹혀요 — 타입 에러, 접근성 위반, TODO 주석 수, 번들 크기. 필요한 건
`{파일: 개수}` JSON 하나와 "늘어난 것만 실패" 규칙뿐입니다.
