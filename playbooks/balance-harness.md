# 밸런스 하네스 — 가상 플레이어 · 합격선 · 수치 덮어쓰기

[헤드리스 하네스](headless-harness.md)가 "시뮬레이션을 렌더러 없이 돌릴 수
있다"까지를 다룬다면, 이 문서는 그 위에서 난이도를 맞추는 절차를 다룹니다.
`moonhalo`(3D 무리 생존 게임, 2026-11-24)에서 봇 하나의 생존 여부만 보다가
난이도를 잘못 읽은 일이 출발점입니다.

봇 6시드 중 5개가 8분을 버틴 결과를 "적당하다"로 읽었습니다. 같은 수치를
실력별 가상 플레이어로 다시 재니 가만히 서 있는 플레이어도 절반이 10분을
버텼고, 영구 강화를 다 사면 초보도 전원 완주했습니다. 합격선 13개 중 3개만
통과하는 상태였습니다.

## 측정 대상 — 봇 하나 대신 실력 구간 다섯

완벽하게 피하는 봇은 실력의 상한선만 알려 줍니다. 사람은 그보다 늦게 보고
덜 정확하게 움직이므로, 실력을 숫자 몇 개로 나눈 가상 플레이어를 여럿 둡니다.

| 가상 플레이어 | 움직임 | 판단 간격 | 위협 시야 | 방향 오차 | 용도 |
|---|---|---|---|---|---|
| 가만히 | 없음 | — | — | — | 아무것도 안 해도 사는지 확인하는 바닥 |
| 무작정 걷기 | 아무 방향 | 1.5초 | 없음 | — | 위협을 안 봐도 사는지 확인하는 바닥 |
| 초보 | 회피 + 수집 | 0.45초 | 3.5 m | ±0.5 rad | 첫 판 |
| 보통 | 회피 + 수집 | 0.22초 | 6 m | ±0.2 rad | 목표 난이도의 기준 |
| 숙련 | 매 프레임 완벽 회피 | 0 | 9 m | 0 | 상한선 |

- 가상 플레이어는 자체 난수를 씁니다. 같은 시드는 같은 입력을 내야 두 결과를
  비교할 수 있습니다.
- 판 밖 성장(영구 강화)이 있으면 "없음 · 전부 구매"를 축으로 하나 더 둡니다.
  `moonhalo`에서는 이 축이 "강화가 판을 끝내 버린다"는 문제를 드러냈습니다.
- 가상 플레이어는 사람을 흉내 내는 것이 아니라 구간의 경계를 잡는 용도입니다.
  실제 사람은 초보와 숙련 사이에 있습니다.

## 지표 — 생존 시간과 함께 원인 계측

생존 시간만으로는 왜 그 값이 나왔는지 알 수 없습니다. 시뮬레이션 안에 계측을
두고 다음을 같이 냅니다.

| 지표 | 답해 주는 질문 |
|---|---|
| 생존 시간 중앙값 · 범위 · 완주 비율 | 얼마나 버티는가, 결과가 양 끝으로 갈리는가 |
| 분당 피격 · 체력 30% 아래로 보낸 시간 비율 | 긴장이 있는가 |
| 근접 압박(플레이어 3 m 안 적 수의 평균) | 무리가 실제로 닿는가 |
| 종류별 피격 · 피해 · 마지막 타격 | 무엇이 죽이는가 |
| 레벨업 간격 · 첫 조합 시각 | 선택에 무게가 있는가 |

- 계측은 판 진행에 영향을 주지 않아야 합니다. 계측을 넣은 뒤에도 결정성
  시험(같은 시드 → 같은 결과)이 통과하는지 확인합니다.
- 원인 계측이 방향을 정했습니다. 기준선에서는 보통 실력 사망의 67%가 보스
  탓이었고, 괴물을 추가한 뒤에는 받는 피해의 66%가 원거리 괴물 한 종에서
  왔습니다. 두 번 모두 생존 시간 표에는 보이지 않던 문제입니다.

## 합격선 — 난이도 목표를 데이터 파일로 고정

난이도 목표를 문장으로 두면 측정할 때마다 해석이 달라집니다. (가상 플레이어,
강화 단계, 지표, 범위)의 목록으로 파일 하나에 둡니다.

```js
{ id: 'T01', persona: 'still',   tier: 'none', metric: 'medianTime', max: 90 },
{ id: 'T04', persona: 'average', tier: 'none', metric: 'medianTime', min: 300, max: 480 },
{ id: 'T06', persona: 'average', tier: 'max',  metric: 'medianTimeGain', min: 60, max: 240 },
{ id: 'T11', persona: 'average', tier: 'none', metric: 'bossDeathShare', max: 0.5 },
```

- 합격선 값은 사람이 정합니다. 에이전트는 제안값을 내고, 사람이 직접 해 본
  체감으로 보정합니다. 수치를 바꿔 합격시키는 것과 합격선을 바꿔 합격시키는
  것을 섞지 않도록, 합격선 변경은 따로 기록합니다.
- 통과 개수가 진행 지표가 됩니다. `moonhalo`는 3 → 7 / 13 이었습니다.
- 판정할 표본이 없는 항목(죽은 판이 없어 사망 원인 비율을 못 내는 경우)은
  불합격이 아니라 "측정 불가"로 따로 표시합니다.

## 수치 실험 — 콘텐츠를 고치지 않는 덮어쓰기

수치를 바꿔 볼 때마다 콘텐츠 파일을 고치면 되돌리기가 번거롭고 무엇을
바꿨는지 흐려집니다. 실행 인자로 덮어쓰고 결과를 이름 붙여 저장합니다.

```sh
pnpm balance                                        # 기준선 저장(base)
pnpm balance --label hp2 --set "enemies.*.hp*=2"    # 가설 하나
pnpm balance --compare base hp2                     # 두 결과 비교
```

가설 하나에 실험 하나를 대응시키면, 어느 손잡이가 센지와 함께 **수치로는
풀리지 않는 항목**이 갈립니다.

| 실험 (`moonhalo`, 시드 8) | 보통 실력 생존 | 합격 |
|---|---|---|
| 기준선 | 10:00 | 3 |
| 괴물 체력 ×1.5 | 8:03 | 5 |
| 괴물 체력 ×2 | 4:42 | 5 |
| 괴물 속도 ×1.5 | 10:00 | 7 |
| 무기 피해 ×0.5 | 8:05 | 5 |

어떤 값에서도 세 항목은 통과하지 못했습니다. 그래서 수치 조정을 멈추고
괴물 행동 세 가지(플레이어보다 빠른 추격 · 원거리 탄 · 발밑 폭발 원)를
추가하는 쪽으로 결정했습니다. 확정한 값만 콘텐츠 파일에 옮기고, 옮긴 뒤에는
덮어쓰기 없이 다시 재서 같은 결과가 나오는지 확인합니다.

## 실행 시간 — 한 번에 1분 안

느린 하네스는 돌리지 않게 됩니다. (가상 플레이어 × 강화 단계 × 시드)를
프로세스 여러 개로 나눠 `moonhalo`는 10분짜리 판 64개를 약 40초에, 128개를
87초에 돌립니다(12코어).

- 탐색은 시드 8개, 확정 전에는 16개 이상으로 잽니다. 같은 구성의 보통 실력
  생존 중앙값이 시드 8개에서 3:39, 16개에서 4:04 로 나왔습니다. 시드 8개의
  30초 차이는 읽지 않습니다.
- 다른 에이전트가 같은 기계에서 빌드 · 생성을 돌리는 동안에는 2~3배
  느려집니다. 명령에는 항상 `timeout`을 겁니다.

## 진행 순서 — 기준선 · 가설 실험 · 반영 · 재측정

1. 기준선을 재서 저장합니다. 통과 개수와 실패 항목이 출발점입니다.
2. 가설마다 덮어쓰기 실험을 하나씩 돌려 손잡이의 세기를 봅니다.
3. 어떤 값에서도 안 풀리는 항목은 구조 변경(행동 · 규칙 추가) 대상으로
   분류합니다.
4. 확정한 값과 구조 변경을 콘텐츠에 반영합니다.
5. 덮어쓰기 없이, 시드를 늘려 다시 잽니다.
6. 바꾼 것 · 전후 표 · 남은 원인을 프로젝트 문서에 기록합니다.
7. 사람이 직접 해 보고 합격선 값을 보정합니다.

## 함정 — moonhalo 에서 실제로 겪은 것

**가상 플레이어가 새 위험을 못 보면 그 위험이 과대평가됩니다.** 원거리 탄을
쏘는 괴물을 넣자 숙련 봇까지 전원이 2~5분 사이에 죽었습니다(중앙값 3:25).
봇이 탄을 위협으로 인식하지 못했기 때문입니다. 탄의 진행 경로에서 비켜서는
회피를 넣자 숙련 봇의 완주가 0%에서 100%로 바뀌었습니다. 새 공격 유형을 넣을
때는 가상 플레이어의 인지도 같은 변경에 포함합니다.

**덮어쓰기는 못 찾으면 실패해야 합니다.** 경로 정규식이 `hp*=3` 의 `*` 를
경로 쪽으로 읽어 아무 값도 바꾸지 못한 적이 있습니다. 작업자가 "아무 값도 못
찾음"으로 실패하고 실행기가 결과 파일을 쓰지 않아서 바로 드러났습니다.
조용히 넘어갔다면 "변화 없음"이라는 가짜 결과가 남았을 것입니다.

**셸 변수에 옵션 묶음을 담으면 통째로 무시될 수 있습니다.** zsh 는 따옴표
없는 변수를 단어로 쪼개지 않습니다. `$OPTS` 에 `--set a --set b` 를 담아
넘겼더니 인자 하나로 전달되어 덮어쓰기가 적용되지 않았고, 결과는 정상적으로
출력됐습니다. 실행기가 적용한 덮어쓰기를 결과 머리에 다시 찍게 하고, 그 줄을
확인한 뒤에 수치를 읽습니다.

**완벽한 봇이 기준인 항목은 사람과 어긋납니다.** "숙련 + 강화 전부"의 완주
비율은 봇이 사람보다 잘 피해서 끝까지 100%로 남았습니다. 이런 항목은
합격선에서 빼지 말고 한계로 적어 둡니다.

## 적용 범위 — 결정적 시뮬레이션과 자동 플레이가 되는 게임

생존 · 로그라이크 · 디펜스처럼 판을 자동으로 끝까지 돌릴 수 있는 게임에
맞습니다. 전제는 [헤드리스 하네스](headless-harness.md)와 같습니다 —
시뮬레이션이 렌더러를 import 하지 않고, 시드가 결과를 결정해야 합니다.

하네스가 재지 못하는 것은 사람이 확인합니다. 탄이 눈에 잘 보이는지, 피하는
동작이 재미있는지, 조작감이 어떤지는 수치로 나오지 않습니다. 합격선을 전부
통과해도 사람이 한 번 해 보기 전까지는 난이도를 확정하지 않습니다.
