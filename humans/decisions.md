# 기술 선택 기록

"왜 그렇게 했는지"를 모았습니다. **결정보다 근거가 오래 갑니다** — 상황이
바뀌면 결정은 뒤집어야 하는데, 근거를 안 적어두면 뒤집어도 되는지 판단할 수가
없기 때문입니다.

각 항목은 실제 코드에 반영되어 있고, 어디를 보면 되는지도 적어뒀습니다.

---

## 렌더링 계층 분리 — 시뮬레이션의 렌더러 무의존

**어디** — `crypt-survivors` · `dungeon-craft` (그리고 유니티 포팅 두 벌)

**결정** — 시뮬레이션 계층이 PixiJS를 절대 import 하지 않습니다.

**근거** — 이걸 지키면 게임 전체를 Node에서 헤드리스로 돌릴 수 있습니다. 그러면
밸런싱이 "몇 판 해보니 어렵다"에서 "24개 시드 중앙값 생존 7분"으로 바뀝니다.
게임은 손으로 테스트하기 가장 어려운 종류의 소프트웨어인데, 이 규칙 하나가
그걸 자동화 가능하게 만들어줍니다.

**대가** — 렌더러가 필요한 정보를 시뮬에서 직접 못 읽습니다. 이벤트로 넘겨야
해서 중간 계층이 하나 더 생깁니다.

**주의** — 이 불변식은 어겨도 오류가 나지 않습니다. 그래서 `crypt-survivors`에는
하네스가 본 게임과 갈라지지 않았는지 대조하는 검사(`validate-balance-harness`)를
따로 뒀습니다. **하네스를 만들면 하네스의 동기화 검사도 같이 만들어야 합니다.**

## 단일 시간축 — 모든 시각 요소의 오디오 클럭 파생

**어디** — `rhythm-godot`

**결정** — 모든 시각 요소가 `AudioClock.now_ms()`에서 파생됩니다. **Tween 금지.**

**근거** — Tween은 프레임 시간을 따르는 **두 번째 시간축**입니다. 오디오 클럭과
프레임 클럭은 반드시 갈리고, 리듬게임에서 그건 곧 판정 오류기 때문입니다.

같은 이유로 캘리브레이션 오프셋을 클럭 **안에서** 빼지 않습니다 — 클럭 내부에
넣으면 단조 증가 클램프가 오발합니다. 오프셋은 판정 시점에서 뺍니다.

**대가** — Godot이 기본 제공하는 애니메이션 도구를 대부분 못 씁니다.

**검증** — 통합 씬은 `--audio-driver CoreAudio`가 **필수**입니다. 기본 Dummy로
돌리면 -4% 드리프트가 생겨서 측정 자체가 무의미해집니다.

## 외부 데이터 검증 — 파싱 단계 Zod 게이트

**어디** — `osm-walker` (`lib/schemas.ts`) · `pig-ma` (`src/schemas/`)

**결정** — 외부에서 들어오는 건 파싱 단계에서 Zod로 검증합니다. 통과한 것만
안쪽 레이어로 보냅니다.

**근거** — Overpass API 응답은 스키마가 느슨하고 자주 빕니다. 검증을 안 하면
`undefined`가 씬 그래프 깊숙이까지 흘러 들어가서, 터지는 곳과 원인이 멀어집니다.

`pig-ma`에서는 이게 **비대칭**이었습니다 — localStorage 복원 경로에는 검증이
있는데 파일 import 경로에는 없었습니다. 같은 데이터가 다른 문으로 들어오면 같은
검사를 받아야 합니다. 지금은 양쪽 다 통과시키고, **깨진 객체는 파일 전체를
거절하지 않고 걸러내면서 몇 개를 버렸는지 알려줍니다.**

## 좌표계 구분 — 타입 3종 · 변환 파일 일원화

**어디** — `osm-walker` (`utils/coordinates.ts`)

**결정** — WGS84 `{lat,lng}` · LocalXZ `{x,z}` · Screen NDC를 서로 다른
타입으로 두고, 변환은 **파일 하나에서만** 합니다.

**근거** — 지도 프로젝트 버그의 대부분이 좌표계 혼동입니다. 셋 다 그냥 숫자
두 개라서 타입을 안 나누면 컴파일러가 못 잡습니다. 나눠두면 잘못 넘기는 순간
빨개집니다.

## 외부 API 호출 게이트 — 전역 직렬 큐 · 적응형 간격

**어디** — `stock-pulse` (`kisFetch`)

**결정** — 모든 KIS 호출이 전역 직렬 큐를 통과합니다. 간격은 **적응형** —
5xx/429면 ×1.6, 성공하면 −15ms (200~1600ms 범위).

**근거** — 라우트가 각자 호출하면 서로를 밀어냅니다. 실측으로 서로 다른 종목
연속 조회에서 **6/10 실패**했고, 게이트 도입 후 **0/12**이 되었습니다.
고정 간격은 TR마다 상한이 달라서 항상 틀렸습니다.

**의도적으로 안 한 것** — **게이트에서 자동 재시도하지 않습니다.** 주문 호출까지
재시도되면 중복 주문이기 때문입니다. 재시도는 호출자 책임으로 남겼습니다.

**관련 규칙** — 실데이터가 없으면 목 데이터가 아니라 `-`를 보여줍니다.
목은 실제와 3배 이상 벌어집니다(삼성전자 시총 468조 vs 1,552조). 그럴듯한
거짓이 빈칸보다 나쁩니다.

## 뷰·편집 공용 상수 — 단일 import 소스

**어디** — `pig-ma` (`src/constants/`)

**결정** — padding · lineHeight · fontSize를 상수 파일에 모으고, Konva 렌더링
경로와 HTML 편집 오버레이가 **같은 값을 import** 합니다.

**근거** — 텍스트를 두 엔진으로 그립니다(보기: Konva / 편집: Tiptap HTML).
값이 1px만 어긋나도 더블클릭하는 순간 글자가 튑니다. 하드코딩하면 반드시
갈립니다.

**같은 부류의 함정** — HTML 오버레이의 zoom 처리입니다. `fontSize × zoom`을
하면 이중 스케일링이 됩니다. CSS `transform: scale()`로 처리해야 내부 요소가
전부 한 번만 스케일됩니다.

## 린트 부채 베이스라인 — 파일별 고정 · 단방향 감소

**어디** — `pig-ma` (`scripts/lint-gate.js`)

**결정** — 기존 위반을 **파일별 개수로 고정**하고 늘어난 파일만 실패시킵니다.

**근거** — 린터를 한 번도 안 돌린 레포(실측 eslint 264건, tsc 523건)에
`eslint .`를 게이트로 붙이면 아무것도 통과하지 못합니다. 그렇다고 미루면 새
위반이 계속 섞입니다. 베이스라인은 **내려가는 쪽으로만** 움직이게 해서 부채가
되돌아올 경로를 없앴습니다.

**가른 기준** — 기계적으로 안전한 것(타입 내로잉 523건)은 전량 청산하고,
판단이 필요한 것(effect 안 setState 등)은 베이스라인으로 뒀습니다. 이걸 안
가르면 "언젠가 다 고치면 게이트 세우자"에 갇혔습니다.

## 외부 정답 대조 — KASI·골든 코퍼스 검증

**어디** — `myeongri-seojae` (`verify-kasi.ts` · `verify-python.ts` · 골든 코퍼스)

**결정** — 절기 계산을 천체력으로 1900~2050 전 구간 검증하고, 그 위에
한국천문연구원(KASI) 공식 값과 한 번 더 대조합니다.

**근거** — **"내 구현 둘이 서로 맞다"와 "공식 기관과 맞다"는 다른 문장입니다.**
한국에서 통용되는 절기 시각의 최종 권위는 KASI이니까, 한 번은 직접 물어봅니다.

같은 패턴이 유니티 JRPG 포팅에도 있습니다 — C# 전투 코드가 원본 JS와 **비트
동일**한지 골든 코퍼스로 diff 합니다. "돌아간다"가 아니라 "원본과 같다"를
증명하는 것입니다.

## 룰 문서 구조 — 분류 어휘 차용 · flat 유지

**어디** — 각 레포 `.claude/rules/` · guk-lab `harness/README.md`

**결정** — 실무 프로젝트의 룰 분류 체계(components / hooks / patterns /
style / workflows …)에서 **분류 어휘는 빌리되, 디렉토리 분리는 하지
않습니다.** 룰 파일은 flat을 유지합니다 (2026-08-25).

**근거** — 실무 레포는 룰이 수십 개라 디렉토리 분류가 이득이지만, 토이는
레포당 1~18개입니다. 가장 큰 pig(18개)도 CLAUDE.md의 적용 경로 표가 이미
색인 역할을 하고 있어, 디렉토리로 옮기면 참조 경로가 전부 깨지는 비용이
분류 이득보다 큽니다. 문서 구조가 코드보다 무거워지는 순간 부채가 됩니다.

**다시 볼 때** — 한 레포의 룰이 20개를 넘거나, 에이전트 정의가 5개를 넘어
탐색이 실제로 불편해지면 그때 디렉토리 분리를 다시 판단합니다.

## 결정의 번복 조건 — 근거 유효성 확인

여기 적힌 것 중 절대적인 건 없습니다. 다만 뒤집을 때는 **근거가 아직 유효한지**
부터 확인하면 됩니다. 예를 들어 "시뮬은 렌더러를 모른다"는 헤드리스 검증이
필요할 때만 값어치가 있습니다. 그게 필요 없는 프로젝트라면 이 규칙도 필요
없는 것입니다.

아직 **채택하지 않은** 제안도 남겨둡니다 — `pig-ma/docs/proposals/`에
`CanvasObject` props 분리 리팩토링이 "미채택" 상태로 있습니다. 완료된 것과
섞어두면 나중에 이미 한 줄 알게 되기 때문입니다.
