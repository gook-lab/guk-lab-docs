# 기술 선택 기록

"왜 그렇게 했는가"를 모았다. **결정보다 근거가 오래 간다** — 상황이 바뀌면
결정은 뒤집어야 하는데, 근거를 안 적어 두면 뒤집어도 되는지 판단할 수 없다.

각 항목은 실제 코드에 반영되어 있고, 어디를 보면 되는지 적어 뒀다.

---

## 렌더링 계층을 데이터에서 떼어낸다

**어디** — `crypt-survivors` · `dungeon-craft` (그리고 유니티 포팅 두 벌)

**결정** — 시뮬레이션 계층이 PixiJS 를 절대 import 하지 않는다.

**근거** — 이걸 지키면 게임 전체를 Node 에서 헤드리스로 돌릴 수 있다. 그러면
밸런싱이 "몇 판 해보니 어렵다"에서 "24개 시드 중앙값 생존 7분"으로 바뀐다.
게임은 손으로 테스트하기 가장 어려운 종류의 소프트웨어인데, 이 규칙 하나가
그걸 자동화 가능하게 만든다.

**대가** — 렌더러가 필요한 정보를 시뮬에서 직접 못 읽는다. 이벤트로 넘겨야 해서
중간 계층이 하나 더 생긴다.

**주의** — 이 불변식은 조용히 깨진다. 그래서 `crypt-survivors` 에는
하네스가 본 게임과 갈라지지 않았는지 대조하는 검사(`validate-balance-harness`)가
따로 있다. **하네스를 만들면 하네스의 동기화 검사도 만들어야 한다.**

## 시간축은 하나만 둔다

**어디** — `rhythm-godot`

**결정** — 모든 시각 요소가 `AudioClock.now_ms()` 에서 파생된다. **Tween 금지.**

**근거** — Tween 은 프레임 시간을 따르는 **두 번째 시간축**이다. 오디오 클럭과
프레임 클럭은 반드시 갈리고, 리듬게임에서 그건 곧 판정 오류다.

같은 이유로 캘리브레이션 오프셋을 클럭 **안에서** 빼지 않는다 — 클럭 내부에
넣으면 단조 증가 클램프가 오발한다. 오프셋은 판정 시점에서 뺀다.

**대가** — Godot 이 기본 제공하는 애니메이션 도구를 대부분 못 쓴다.

**검증** — 통합 씬은 `--audio-driver CoreAudio` 가 **필수**다. 기본 Dummy 로
돌리면 -4% 드리프트가 생겨 측정 자체가 무의미해진다.

## 외부 데이터는 문 앞에서 막는다

**어디** — `osm-walker` (`lib/schemas.ts`) · `pig-ma` (`src/schemas/`)

**결정** — 외부에서 들어오는 것은 파싱 단계에서 Zod 로 검증한다. 통과한 것만
안쪽 레이어로 보낸다.

**근거** — Overpass API 응답은 스키마가 느슨하고 자주 빈다. 검증을 안 하면
`undefined` 가 씬 그래프 깊숙이까지 흘러 들어가서, 터지는 곳과 원인이 멀어진다.

`pig-ma` 에서는 이게 **비대칭**이었다 — localStorage 복원 경로에는 검증이
있는데 파일 import 경로에는 없었다. 같은 데이터가 다른 문으로 들어오면 같은
검사를 받아야 한다. 지금은 양쪽 다 통과시키고, **깨진 객체는 파일 전체를
거절하지 않고 걸러내면서 몇 개를 버렸는지 알린다.**

## 좌표계는 타입으로 분리한다

**어디** — `osm-walker` (`utils/coordinates.ts`)

**결정** — WGS84 `{lat,lng}` · LocalXZ `{x,z}` · Screen NDC 를 서로 다른
타입으로 두고, 변환은 **파일 하나에서만** 한다.

**근거** — 지도 프로젝트 버그의 대부분이 좌표계 혼동이다. 셋 다 그냥 숫자
두 개라 타입을 안 나누면 컴파일러가 못 잡는다. 나누면 잘못 넘기는 순간 빨개진다.

## 남의 API 앞에 게이트를 하나 세운다

**어디** — `pulse-dashboard` (`kisFetch`)

**결정** — 모든 KIS 호출이 전역 직렬 큐를 통과한다. 간격은 **적응형** —
5xx/429 면 ×1.6, 성공하면 −15ms (200~1600ms 범위).

**근거** — 라우트가 각자 호출하면 서로를 밀어낸다. 실측으로 서로 다른 종목
연속 조회에서 **6/10 실패**했고, 게이트 도입 후 **0/12** 이 됐다.
고정 간격은 TR마다 상한이 달라 항상 틀린다.

**의도적으로 안 한 것** — **게이트에서 자동 재시도하지 않는다.** 주문 호출까지
재시도되면 중복 주문이다. 재시도는 호출자 책임으로 남겼다.

**관련 규칙** — 실데이터가 없으면 목 데이터가 아니라 `-` 를 보여준다.
목은 실제와 3배 이상 벌어진다(삼성전자 시총 468조 vs 1,552조). 그럴듯한 거짓이
빈칸보다 나쁘다.

## 뷰와 편집이 같은 상수를 본다

**어디** — `pig-ma` (`src/constants/`)

**결정** — padding · lineHeight · fontSize 를 상수 파일에 모으고, Konva 렌더링
경로와 HTML 편집 오버레이가 **같은 값을 import** 한다.

**근거** — 텍스트를 두 엔진으로 그린다(보기: Konva / 편집: Tiptap HTML).
값이 1px 만 어긋나도 더블클릭하는 순간 글자가 튄다. 하드코딩하면 반드시 갈린다.

**같은 부류의 함정** — HTML 오버레이의 zoom 처리. `fontSize × zoom` 을 하면
이중 스케일링이 된다. CSS `transform: scale()` 로 처리해야 내부 요소가 전부
한 번만 스케일된다.

## 부채 위에 게이트를 세운다

**어디** — `pig-ma` (`scripts/lint-gate.js`)

**결정** — 기존 위반을 **파일별 개수로 고정**하고 늘어난 파일만 실패시킨다.

**근거** — 린터를 한 번도 안 돌린 레포(실측 eslint 264건, tsc 523건)에
`eslint .` 를 게이트로 붙이면 아무것도 통과 못 한다. 그렇다고 미루면 새 위반이
계속 섞인다. 베이스라인은 **내려가는 쪽으로만** 움직이게 해서 부채가 되돌아올
경로를 없앤다.

**가른 기준** — 기계적으로 안전한 것(타입 내로잉 523건)은 전량 청산, 판단이
필요한 것(effect 안 setState 등)은 베이스라인. 이걸 안 가르면 "언젠가 다
고치면 게이트 세우자"에 갇힌다.

## 정답이 밖에 있으면 그것과 대조한다

**어디** — `myeongni-seojae` (`verify-kasi.ts` · `verify-python.ts` · 골든 코퍼스)

**결정** — 절기 계산을 천체력으로 1900~2050 전 구간 검증하고, 그 위에
한국천문연구원(KASI) 공식 값과 한 번 더 대조한다.

**근거** — **"내 구현 둘이 서로 맞다"와 "공식 기관과 맞다"는 다른 문장이다.**
한국에서 통용되는 절기 시각의 최종 권위는 KASI 이므로 한 번은 직접 물어본다.

같은 패턴이 유니티 JRPG 포팅에도 있다 — C# 전투 코드가 원본 JS 와 **비트 동일**
한지 골든 코퍼스로 diff 한다. "돌아간다"가 아니라 "원본과 같다"를 증명한다.

## 뒤집을 수 있게 적어 둔다

여기 적힌 것 중 절대적인 건 없다. 다만 뒤집을 때는 **근거가 아직 유효한지**
부터 확인하면 된다. 예를 들어 "시뮬은 렌더러를 모른다"는 헤드리스 검증이
필요할 때만 값어치가 있다. 그게 필요 없는 프로젝트라면 이 규칙도 필요 없다.

아직 **채택하지 않은** 제안도 남겨 둔다 — `pig-ma/docs/proposals/` 에
`CanvasObject` props 분리 리팩토링이 "미채택" 상태로 있다. 완료된 것과 섞어
두면 나중에 이미 한 줄 알게 된다.
